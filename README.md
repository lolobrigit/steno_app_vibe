# STENO Desktop

Нативное приложение **STENO** для **Windows, Linux и macOS** — оболочка над
веб-версией [steno_vibe](https://github.com/lolobrigit/steno_vibe)
(расшифровка речи локально: Whisper + диаризация спикеров + LLM-постобработка).

Приложение даёт веб-версии «настольные» возможности: трей, быструю запись
звука и видео с системных устройств, предзагрузку моделей по прямым ссылкам
и контроль памяти GPU/CPU.

## Что умеет

| # | Требование | Как реализовано |
|---|------------|-----------------|
| 1 | Веб-версия внутри | Окно Electron загружает либо локальную сборку фронтенда (`web/dist`, через встроенный сервер на 127.0.0.1 — это secure context для WebGPU/IndexedDB), либо удалённый URL (по умолчанию `https://vlcast.com/whisper`). Режим переключается настройкой `appMode` |
| 2 | Сворачивание в трей/панель | Закрытие окна прячет его в трей (`minimizeToTray`); приложение живёт в трее, пока не выбран «Выход». На macOS — иконка в menu bar |
| 3 | Запись аудио и видео с устройств системы | **Микрофон** — `getUserMedia`. **Системный звук** — `desktopCapturer` + `setDisplayMediaRequestHandler` с `audio: 'loopback'` (WASAPI loopback, Windows из коробки; на macOS нужен виртуальный драйвер типа BlackHole; на Linux — monitor-источник PipeWire/PulseAudio). **Видео** — экран, отдельное окно или камера, запись через `MediaRecorder` (webm) |
| 4 | Меню трея по правой кнопке | Быстрый переход: «Новая расшифровка», «Настройки и модели», «Хранилище / загрузки», «История / проекты», «Выгрузить модели из памяти», «Выход». Навигация выполняется кликом по aria-label элементам веб-приложения (en/ru) |
| 5 | Левая кнопка — быстрый старт | Компактное окно у трея: выбор «микрофон / системный звук / экран / окно / камера», для экрана и окна — визуальный выбор источника с превью, опции «со звуком системы» и «+ микрофон». После остановки запись сохраняется в папку записей и одной кнопкой отправляется на расшифровку в основное окно |
| 6 | Предзагрузка моделей | Менеджер загрузок (`electron/models.cjs`): прямые ссылки Hugging Face (`huggingface.co`/`hf-mirror.com`, вида `…/resolve/<rev>/<file>`) или произвольные URL; папка моделей выбирается пользователем. Очередь по одной загрузке, докачка с того же байта (HTTP Range, переживает перезапуск), проверка свободного места, отмена удаляет частичные файлы. Скачанные файлы подставляются в веб-приложение вместо сети — перехватчик протокола отдаёт локальный файл по «родному» пути репозитория |
| 7 | Модели в GPU/CPU только когда нужны | Сама веб-версия загружает веса лениво (transformers.js поднимает модель при первом обращении). Из трея доступно «Выгрузить модели из памяти» — в страницу отправляется событие `steno:unload-models`, по которому приложение может сбросить загруженные веса |

## Сборка и запуск

```bash
npm install
npm run fetch-web   # клонировать и собрать веб-фронтенд в web/dist
npm start           # запуск в режиме разработки
```

Либо используйте локальную копию веб-репозитория:

```bash
node scripts/fetch-web.cjs --local ../steno_vibe
```

> Без `fetch-web` приложение тоже работает — в режиме `remote` оно открывает
> развёрнутую веб-версию (настраивается `appUrl`).

### Установщики

```bash
npm run dist:win    # Windows: NSIS (.exe)
npm run dist:linux  # Linux: AppImage + .deb
npm run dist:mac    # macOS: .dmg
```

Собранные пакеты появятся в `release/`. Готовые сборки под все три ОС
собираются в CI (см. `.github/workflows/build.yml`).

## Настройки

Хранятся в `userData/steno-desktop.json`:

| Ключ | По умолчанию | Назначение |
|------|--------------|------------|
| `appMode` | `remote` | `local` — локальная сборка `web/dist`, `remote` — URL |
| `appUrl` | `https://vlcast.com/whisper` | адрес веб-версии в режиме `remote` |
| `modelsDir` | `userData/models` | папка предзагруженных моделей |
| `recordingsDir` | `~/Videos/STENO` | куда складывать записи быстрого старта |
| `minimizeToTray` | `true` | закрытие окна прячет его в трей |
| `autoLaunch` | `false` | автозапуск вместе с системой |
| `startMinimized` | `false` | стартовать свёрнутым в трей |

## Структура

```
electron/
  main.cjs      — окна, трей, IPC, перехват загрузок моделей, захват медиа
  tray.cjs      — иконка трея, меню ПКМ, быстрый старт по ЛКМ
  models.cjs    — менеджер загрузок моделей (очередь, Range-докачка, resume)
  server.cjs    — встроенный HTTP-сервер для локальной web/dist
  preload.cjs   — window.stenoNative: мост веб-приложения к системе
  settings.cjs  — настройки (JSON, атомарная запись)
quickstart/     — окно быстрой записи (UI выбора источника + MediaRecorder)
scripts/
  fetch-web.cjs — клонирование и сборка веб-фронтенда
  make-icon.cjs — генерация build/icon.png без зависимостей
build/          — entitlements для macOS (иконка генерируется скриптом)
```

## Интеграция с веб-приложением

- **Файлы на расшифровку** передаются через скрытый `input[type=file]`
  панели источника (тот же путь, что и выбор файла руками).
- **Навигация из трея** — клики по элементам с известными aria-label
  (поддержаны русская и английская локали).
- **Выгрузка моделей** — событие `window` `steno:unload-models`;
  веб-приложение может подписаться и сбросить веса.
- **Модели из папки** — запросы к `huggingface.co/*/resolve/*` и
  `hf-mirror.com/*/resolve/*` обслуживаются локальным файлом, если он уже
  скачан в `modelsDir` (структура `owner/model/resolve/rev/file`).

## Ограничения платформ

- **Системный звук**: Windows — WASAPI loopback, работает сразу.
  macOS — требуется виртуальный аудиодрайвер (BlackHole и аналоги).
  Linux — зависит от PipeWire/PulseAudio (нужен monitor-источник).
- **macOS**: при первом использовании система спросит разрешения на микрофон,
  камеру и запись экрана (см. `build/entitlements.mac.plist`).
- Локальные модели подхватываются, только если веб-приложение запрашивает
  те же ревизии файлов, что были скачаны.
